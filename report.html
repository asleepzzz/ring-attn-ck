Ring Attention on CK FMHA

Zigzag ring attention（forward + backward），每個 ring step 直接呼叫 CK Tile FMHA；合併與通訊在 CK 外面（PyTorch + RCCL）。 量測環境見性能一節。

1. 為什麼要 ring attention

序列長度 S 很長時，單張 GPU 放不下或算太久。做法是把序列切成 W 份分給 W 張 GPU：每張卡的 Q 留在本地不動，K/V 沿著一個環（rank r → r+1）轉一圈。 轉完 W 步，每張卡的 Q 都看過全部的 K/V，得到和單卡完全相同的結果。每一步的計算都可以和「把下一份 K/V 傳過來」重疊。

2. Zigzag 切分：讓 causal 的工作量平均

Causal attention 只有下三角要算。若把序列照順序切（rank 0 拿最前面），最後一個 rank 要算的區塊比第一個多很多，大家都得等它。 Zigzag 把序列切成 2W 塊，rank r 拿第 r 塊和第 2W−1−r 塊，一前一後互補，每個 rank 的工作量就一樣了。

照順序切（W = 4）

格子 = (Q 塊, K 塊)；顏色 = 負責的 rank；斜線 = 對角塊（內部要 causal mask）

Zigzag 切（W = 4）

rank r 持有第 r 與第 7−r 塊

下方長條是每個 rank 要算的工作量（以一個完整塊為 1、對角塊為 0.5）。照順序切最多差 7 倍；zigzag 每個 rank 都是 8。

每一步要算什麼（rank r，第 t 步拿到 src = (r − t) mod W 的 K/V）

本地序列長 2c（兩塊各 c）。因為 zigzag 的排法，除了第 0 步以外的每一步都不需要 mask，而且大小都一樣：

step條件呼叫 CK原因
t = 0自己的 K/Vfwd(Q, K, V, causal)兩塊在全域順序上前後排好，本地 causal 剛好正確
t > 0src < rfwd(Q, K[:c], V[:c])，無 mask本地兩塊 Q 都在 src 的前一塊之後、都在 src 的後一塊之前
t > 0src > rfwd(Q[c:], K, V)，無 mask只有本地後一塊 Q 看得到 src，而且看得到 src 全部

3. 怎麼把每一步的結果合起來（Forward）

CK 每一步回傳兩樣東西：這一塊 K/V 算出的輸出 Ot（已用這一塊自己的 softmax 分母歸一化）和 LSEt = log Σ exp(score)（fp32）。 有 LSE 就能把不同 K/V 塊的結果精確合併，等價於一次看完全部 K/V：

lsenew = log( exp(lse) + exp(LSEt) )
Onew   = O · exp(lse − lsenew) + Ot · exp(LSEt − lsenew)

累加器 O、lse 都用 fp32，最後才轉成 bf16。若用 bf16 逐步合併，每一步都多一次捨入。

4. Backward

  • K/V 再沿環轉一次。每一步呼叫 CK bwd，但傳入的 out 和 LSE 是 forward 合併後的全域值。 這樣 kernel 內部的 P = exp(S − lse全域) 和 D = rowsum(dO · O全域) 都和整段 attention 一致，算出來的就是這一塊在完整梯度裡的份量。
  • dQ：每一步的份量在本地用 fp32 累加。
  • dK / dV：屬於某份 K/V 的梯度散落在每張卡上，所以準備一個 fp32 累加器跟著那份 K/V 一起傳。每張卡加上自己的份量再往下傳；轉完一圈後還差一站，多傳一次就回到擁有者手上。

5. 通訊與計算重疊

每一步開始時先發出「把手上的 K/V 傳給下一個、從上一個收下一份」（RCCL batch_isend_irecv，在 RCCL 自己的 stream 上），接著馬上用目前的 K/V 算 attention，算完再等傳輸完成。只要計算比傳輸久，通訊就被藏住了。

示意：一個 rank 的時間軸（非量測資料）

實際每步的計算／通訊時間見第 7 節

每步傳輸量 ≈ 2 · Slocal · Hkv · D · 2 bytes，計算量 ∝ Slocal² · Hq · D。Slocal 越大、Hkv 越小（GQA），越容易藏住。 要注意 RCCL 的 P2P 是用 GPU kernel 搬資料，會佔用一些 CU，跟 attention 搶算力；改用 SDMA（copy engine）可以避免。

已知的浪費：CK bwd 內部每一步都重算 D = rowsum(dO·O) 並跑一次 convert_dq；每一步的輸出先寫成 bf16 再讀回來累加。這些要改 CK 才能消除。

8. 正確性驗證

每個 rank 用相同 seed 產生完整的 Q/K/V/dO，跑 ring 後把 out、dQ、dK、dV 收回來，和兩個參考比：fp32 PyTorch（標準答案）與單卡 CK（誤差預算）。 判定：ring 對 fp32 的最大誤差 ≤ 2 × 單卡 CK 對 fp32 的最大誤差 + 1e-4。另外故意丟掉一個 ring step（反向對照），測試必須判 FAIL。
